# 手动复测：用户指定的短命令

当前优化版已切换为“上游原样dispatch＋经用户同意的short尾部修复”。原版不变，两条压测命令不变。当前补丁与报告位于dispatch目录；旧4way-only二进制在服务器另存为redis-server-optimized.4way-previous。

当前复测只执行下方两条SET/GET命令，通过-n调整持续时间。历史随机key空间及额外预热工况不再用于当前复测。

服务器：192.168.90.158。文件目录：`/home/liupengwei/redis-crc16-20261026/manual`。

## 启动容器

```bash
ssh root@192.168.90.158
docker run --rm -it --name redis-crc16-manual \
  --user 1007:1007 --cpuset-cpus 340,342 \
  --memory 8g --pids-limit 256 --network host \
  --cap-drop ALL --security-opt no-new-privileges \
  --read-only --tmpfs /tmp:rw,size=1g \
  -e HOME=/tmp -e TZ=Asia/Shanghai \
  -v /home/liupengwei/redis-crc16-20261026/manual:/manual:Z \
  -w /manual --entrypoint /bin/bash bb2be08831f4
```

root仅启动容器，容器内UID/GID为1007。当前复测运行期间请勿再启动同端口实例。

## 原版测试

```bash
source /manual/manual_test.sh
start_redis baseline
KEY=$(printf 'k%.0s' {1..64})
taskset -c 342 /manual/bin/redis-benchmark -p 36381 -c 200 -n 10000 -P 16 SET "$KEY" xxx
taskset -c 342 /manual/bin/redis-benchmark -p 36381 -c 200 -n 10000 -P 16 GET "$KEY"
stop_redis
```

## 优化版测试

```bash
start_redis optimized
# 执行上面相同的两条SET/GET命令

```

本次较长复测只将-n改为100000000，每版SET/GET各1亿请求，其他参数保持相同。屏幕输出Redis原生报告。需100亿请求时使用10000000000，客户端已支持64位计数。

也可执行 `run_bench 100000000`，它现在只运行上述两条命令并保存输出，不再发出预热压测。
