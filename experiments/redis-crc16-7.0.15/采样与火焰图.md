# 参数对齐与 CRC16 火焰图

## 手测脚本与简化命令的区别

脚本长，是因为包含单节点集群启动、全槽分配、端口检查、绑核、预热、结果记录和实例停止。实际计时调用仍然是 redis-benchmark。

但脚本负载不与 `redis-benchmark -c 200 -t set,get -n 10000 -P 16` 严格等价：脚本还使用 `-r 10000`，完整64B key、64B value、各20万请求预热；此前报告每项每轮计时1000万请求。该短命令默认不随机化key，value默认3B，原生默认key也不是64B。

原生7.0.15的 `-t` 用逗号分隔，应写 `set,get`，`set.get` 不会选中 SET 或 GET。`-d 64` 是value长度，不是key长度。

下面两条命令满足：200连接，SET与GET各1万请求，pipeline16，固定64B key，value采用原生默认长度3B；不额外预热、不使用随机key空间。先启动手测 Redis，再在手测容器内执行：

```bash
KEY=$(printf 'k%.0s' {1..64})
taskset -c 342 /manual/bin/redis-benchmark -p 36381 -c 200 -n 10000 -P 16 SET "$KEY" xxx
taskset -c 342 /manual/bin/redis-benchmark -p 36381 -c 200 -n 10000 -P 16 GET "$KEY"
```

需64B value时，显式构造VALUE并替换xxx；这与默认3B value属于不同负载。1万请求适合检查流程，百万QPS时仅约10ms，不能据此获得稳定的热点占比或可靠的小幅吞吐差异。

## 原先19.21%的采样方法

宿主机以liupengwei身份对原版Redis的宿主PID采样：

```bash
perf record -e cycles:u -F 499 -p 1405685 \
  -o results/profile-baseline-set.data -- sleep 10
```

原采样未带 `-g` / `--call-graph`，只能做函数级平面热点，不包含完整调用栈，因此不能从原文件补出真实调用栈火焰图。原占比为按采样period加权的用户态cycles占比，非全部CPU时间，非整机占比。

## 新补采的真实火焰图

2026-10-26约19:46，在同一个原版SET长测期间重新采集30秒：

```bash
cd /home/liupengwei/redis-crc16-20261026
perf record -e cycles:u -F 199 --call-graph dwarf,8192 \
  -p 1405685 -o results/profile-baseline-set-dwarf.data -- sleep 30
```

宿主PID是本次采集时的实际值，后续运行应重新核对。新采样5,957个样本，无丢样。CRC16为 **18.74%用户态cycles**，原先10秒采样为19.21%，两次为独立采样窗口。

当前负载：原版Redis 7.0.15，单节点集群、完整64B key且无hash tag、64B value、200连接、pipeline16、随机key空间10000、本机TCP、SET长测。该占比不能视为上述固定key/3B value/1万请求短命令的占比，也不能替代GET或优化版采样。

新采样中的关键调用链完整解析为：

`processInputBuffer → processCommand → getNodeByQuery → keyHashSlot → crc16`

容器的 `/work/...` 路径在宿主不存在，故在 `validation/perf-symfs` 镜像相同路径，放置正在运行的精确Redis二进制及容器libc。使用 `--symfs` 正常解析符号；新版结果无需依靠手工地址推断。部分libc启动栈帧仍显示unknown，Redis/CRC16路径已解析。

```bash
SYMFS="$PWD/validation/perf-symfs"
perf report -i results/profile-baseline-set-dwarf.data --symfs "$SYMFS" \
  --stdio --no-children --sort dso,symbol

perf script -i results/profile-baseline-set-dwarf.data --symfs "$SYMFS" \
  -F comm,pid,tid,time,period,event,ip,sym,dso \
  > results/profile-baseline-set-dwarf.script

perl artifacts/FlameGraph/stackcollapse-perf.pl \
  results/profile-baseline-set-dwarf.script > results/profile-baseline-set-dwarf.folded

perl artifacts/FlameGraph/flamegraph.pl \
  --title 'Redis 7.0.15 baseline SET - user cycles' \
  --subtitle '64B key, 64B value, c200 P16, 30s @199Hz; cycles:u only' \
  --countname cycles --width 1500 \
  results/profile-baseline-set-dwarf.folded > results/profile-baseline-set-flamegraph.svg
```

脚本显式导出period字段，因此火焰图宽度以cycles加权，不是简单数样本。folded总权重为59,575,835,441，CRC16为11,163,552,116，比例18.7384%，与perf report吻合。

工具为Brendan Gregg官方FlameGraph，提交41fee1f99f9276008b7cd112fca19dc3ea84ac32。源码：https://github.com/brendangregg/FlameGraph 。

## 查看方式与文件

- `results/profile-baseline-set-flamegraph.svg`：交互SVG，用浏览器打开；点函数块缩放，Search输入 `crc16` 高亮占比。
- `results/profile-baseline-set-flamegraph.png`：静态预览。
- `results/profile-baseline-set-dwarf-report.txt`：函数热点与调用链文本。
- `results/profile-baseline-set-dwarf.folded`：按cycles加权的折叠调用栈。
- 服务器上的 `results/profile-baseline-set-dwarf.data` 和 `.script`：原始采样和解码调用栈，保留在上述工作目录。
- `flamegraph-raw.tar.gz`：这两个原始文件的本地交付归档，解压后可以重新生成并核验火焰图。

采样阶段会引入一定观测开销；这30秒用于热点归因，不作为新的独立吞吐样本。图中分母只包含被采样Redis进程的用户态cycles，不含内核和等待时间。
