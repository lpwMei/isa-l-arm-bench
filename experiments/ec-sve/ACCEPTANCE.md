# EC 首轮优化验收

本轮只处理 EC 编码，其他需求留作后续独立任务。基线固定为 ISA-L
`8fa1e72fee7338fcfbf829b00f2f407631bd2dba`，不与更旧版本或标量实现比较。

目标在候选结果揭晓前确定：

* 官方 `erasure_code_perf -k 10 -p {4,6,7} -e 1 -s 64K` 的编码吞吐，
  相对同机同编译参数基线分别提高至少 10%。
* 筛选阶段三个重复；选定补丁后重新构建，以七轮交替顺序的独立实验验收。
  同时报告中位数、成对比值和变异系数，保留每一轮原始日志。
* `p=2` 编码和四组单块恢复作为保护项，独立验收中位数下降不超过 3%；
  对未改动内核的噪声结果先复测，不能据此宣称内核进步。
* 完整 `make check`；有针对性的 reference 对照覆盖 SVE/SVE2/默认分派、
  零长度、小长度、非向量整数倍长度、1 至 11 行、1 至 31 个源、
  随机/全1/混合/全0系数。数据和查表空间紧贴不可访问保护页。
* 4 KiB、1 MiB，以及额外的源数量，用三轮检查性能适用范围。
  这些保护项不替代首批三个明确的目标。
* 驱动源码、计时长度、数据生成方式、CPU 亲和性、CFLAGS 不因候选而变化。
  矩阵初始化不计入吞吐，保持官方工具原定义。

免费云环境是 GitHub Actions 的原生 AArch64 runner，上一轮为 Neoverse-N2。
它用于验证方法和筛选补丁。它不是鲲鹏950；本轮成功不等于950验收成功。
950须使用相同基线、补丁、命令与方法重新测试，记录CPU型号、SVE向量长度和工具链。

候选包括：减少3路及以上内核的空间展开量（4→1/2），将“是否需要GF查表”
的判定移至数据循环外；以及仅改变高层分组至两行。保留1/2路原有快路。
